# Работа с репозиторием

- Основная ветка — `main`; рабочие — `feature/<краткая-тема>`.
- Один коммит — одна задача: `fix: prevent title overlap`, `docs: describe setup`.
- Использовать реальные даты и настроенный профиль коммиттера. Не создавать
  заднюю историю; прошлые сведения оформлять документом с источниками.
- UI, данные и production-выкладка — разные операции.
- Не удалять динамические ассеты по отсутствию прямого импорта.
- Сохранять существующие пользовательские правки.

## Перед коммитом

В этом локальном checkout подключён `.githooks/pre-commit`. После нового clone:

```powershell
git config --local core.hooksPath .githooks
```

Hook вызывает safety check и проверку whitespace. На Windows нужен Git for
Windows с shell и Node в PATH. Hook не заменяет CI или ручной просмотр.

```powershell
node tools/repository-check.cjs --staged
git diff --cached --check
git diff --cached --stat
```

Для приложения из `figma-real-layout/`: `npm run test:api`, `npm run build`.
Для UI — браузерная проверка затронутых страниц, кликов, длинных строк,
мобильного и широкого экрана. Не заявлять Figma 1-в-1 без визуального сравнения.

Commit/tag не означают выкладку. Production требует отдельной санкции,
backup и проверок. CI не содержит автодеплоя.

Передавать исходники через приватный remote или защищённый bundle.
Секреты передавать отдельно. До создания remote согласовать владельца,
платформу, название, видимость и участников.
