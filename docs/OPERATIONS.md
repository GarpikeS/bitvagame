# Эксплуатация

Подготовка Git не включает деплой, перенос сервера, DNS или выдачу доступов.

По прежним release-записям frontend отдаётся nginx, API — отдельный процесс.
Ручные скрипты: `figma-real-layout/scripts/deploy-partystore*.sh`.
Секреты задаются environment, не tracked files.

Точные пути/runtime сверять с live-сервером перед выкладкой. Исторические
`release-*.sh` содержат одноразовый baseline/stamp — не запускать повторно.

## Release gate

1. Проверить commit кандидата и рабочее дерево.
2. Repository check, API-тесты, build, соответствующий browser QA.
3. Проверить фактический production baseline и незавершённые чужие работы.
4. Сделать проверенный backup в согласованном контуре.
5. Деплоить только проверенный артефакт под блокировкой, не весь workspace.
6. Проверить SHA index, HTTP/MIME assets, TLS, health и изменённый сценарий.
7. Записать commit, SHA пакета, backup, дату и результаты.

Старые hashed assets сохранять для cached HTML. Frontend rollback — предыдущий
index и assets. Откат API/данных требует отдельной проверки совместимости:
нельзя восстановить старый JSON поверх новых пользовательских записей вслепую.

CI не деплоит. Git tag идентифицирует код, не доказывает выкладку.
